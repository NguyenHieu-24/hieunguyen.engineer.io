THE PROBLEM

Why this project exists.

Prepare model-ready loan data and make a decision-support workflow accessible through a customer and staff interface.

IMPLEMENTATION

What the implementation includes.

  • Built a six-step offline workflow for encoding, feature engineering, selection, splitting, training, and evaluation.
  • Reused saved encoders and ordered model features when preparing new application data.
  • Integrated separate customer and staff views, application storage, SHAP explanations, and what-if analysis.

The data flow.

Raw application→Saved preprocessing→Stacking model→Role-based results

Training and inference

Saved encoders and a common inference module reduce hand-written mapping differences.

Stacking ensemble

The source combines XGBoost, Random Forest, LightGBM, and Gradient Boosting with Logistic Regression.

Application storage

MongoDB is supported with a local JSON fallback. Customer queries are filtered by owner.

EVIDENCE

Results and scope.

The supplied files contain 36,000 training rows and 9,000 test rows. Model scores are intentionally not highlighted here: evaluation needs to be repeated after correcting feature-selection and resampling leakage. This is an academic prototype, not a deployed lending service.

NEXT ITERATION

Limitations and improvements.

  • Feature selection currently runs before the train/test split; fit it only within training data.
  • SMOTE currently runs before cross-validation; move resampling inside each training fold.
  • Step 6 uses fixed parameters rather than loading the Optuna results from Step 5.
  • Confirm the source definition of loan_status before describing class 1 as default risk.
  • Masking display fields does not encrypt stored application data.

REPRODUCE

Running the original project.

Use synthetic application data. Install requirements, configure a local demo backend, create demo users, and launch Streamlit. Some pipeline paths require adjustment outside Windows.
