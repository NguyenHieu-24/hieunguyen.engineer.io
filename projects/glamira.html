THE PROBLEM

Why this project exists.

Turn e-commerce event fields into more useful product and geographic attributes for analysis.

IMPLEMENTATION

What the implementation includes.

  • Extracted product identifiers and URLs from selected MongoDB event types.
  • Collected product names from page HTML using requests and Beautiful Soup.
  • Aggregated unique IP addresses and enriched them with IP2Location attributes.

src/process_ip.py · src/product_pipeline.py

EVIDENCE

Results and scope.

The supplied archive covers extraction and enrichment. Its ip_locations.csv is a Git LFS pointer rather than the underlying dataset. BigQuery, dbt, and Looker implementations are not included in this source snapshot.

NEXT ITERATION

Limitations and improvements.

  • Product requests are sequential and do not include a persistent retry mechanism.
  • The IP script clears its destination collection before processing; use a disposable demo database when reproducing.
  • Warehouse models and dashboards require separate implementation evidence.

REPRODUCE

Running the original project.

Prepare a local MongoDB countly.summary collection and the required IP2Location database. Review destination handling, then run the product and IP scripts separately on demo data.

The portfolio package contains these case studies, not the original project datasets or services.
