THE PROBLEM

Why this project exists.

Make log flow visible across services and provide a local environment for exploring operational metrics.

IMPLEMENTATION

What the implementation includes.

  • Defined six services in a Docker Compose environment.
  • Configured Fluent Bit to send sample JSON events through Logstash into Elasticsearch.
  • Included Kibana for log inspection and Prometheus with Grafana for metrics exploration.

docker-compose.yml · fluent-bit/ · logstash/ · prometheus/

ARCHITECTURE

The data flow.

Sample event→Fluent Bit + Logstash→Elasticsearch→Kibana

High-level illustration of the implemented workflow.

Synthetic event source

Fluent Bit uses a dummy input so the example does not require live banking data.

TCP JSON ingestion

Logstash accepts JSON over TCP and writes events to the bank-logs index.

Separate metrics path

Prometheus scrapes itself. A Grafana data source and panels require configuration.

EVIDENCE

Results and scope.

The source is a local demonstration associated with the observability topics in my experience. It does not establish production uptime, financial-record volume, or monitoring coverage of a live bank system.

NEXT ITERATION

Limitations and improvements.

  • Application and host metrics exporters are not configured.
  • Grafana dashboards and a data source are not provisioned in the source.
  • Persistent volumes and an end-to-end ingestion check are useful next steps.

REPRODUCE

Running the original project.

Use the root docker-compose.yml. Start with docker compose up -d, inspect service logs, and check bank-logs in Kibana. Do not start the duplicate nested Compose configuration.

The portfolio package contains these case studies, not the original project datasets or services.
